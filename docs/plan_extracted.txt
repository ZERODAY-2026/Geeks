1. Executive summary and feasibility verdict
LexiShield reads a rental agreement, employment contract, freelance agreement or legal notice on the user's own machine. It explains the important clauses in plain language, says clearly when the document is silent on something, and cites the exact passage behind every statement. It refuses to give legal verdicts and points the user to the right kind of professional. No document content ever leaves the device, and we can prove it.
1.1 What makes this build different from the other PS2 teams

Claim-level verification gate
Every quote is matched against the source and always displayed from the source. A distortion check confirms that every amount, duration, date, negation and party role in the plain-language explanation appears unchanged in the cited text.

The verifier auto-snaps altered quotes back to the source.
If Gemma changes "shall not" to "shall", snapping the citation back hides a wrong explanation.

The sanitizer strips hidden text and injection phrases from the document.
Changing a legal document is wrong, and hidden text is itself a red flag the user should see.

3.1 Jurisdiction auto-detection (deterministic first, Gemma second)
Signals: "governed by the laws of …", "courts at <city> shall have exclusive jurisdiction", lists of Indian states and cities, ₹ / Rs. / INR / lakh / crore, "e-stamp" or "stamp paper", references to Indian Acts, and $ / £ plus US state or UK place names.
A score is computed per candidate. Gemma confirms only when the signals conflict. The output is {country, state, confidence, evidence_spans[]}.
If confidence is low, the result is jurisdiction = UNKNOWN. Cards then carry "jurisdiction-dependent: check local law with a professional" and no statute context is shown.
Effect: jurisdiction selects the checklist pack variant, the escalation table and whether statute context is shown. It never changes what the document is said to state.
Scope statement for the README (honest scoping is rewarded)
"LexiShield is tuned and tested on Indian residential rental and employment documents in English. Freelance agreements and legal notices get a generic checklist. US/UK documents get jurisdiction flags only. The tool does not judge legal validity, does not support scanned PDFs without the optional OCR, and has not been validated by lawyers."

6. System architecture
Figure 1 (next page) shows the full system. It has ten subsystems in five pipeline stages, wrapped by a Local Trust Boundary and a Privacy Kernel. Each module is small (about 80–300 lines) with one job, so three developers can build in parallel and each module has its own unit tests.
6.1 Layer responsibilities
Layer
Responsibility
Key design decisions
API Gateway
HTTP surface for the frontend and the CLI; validation; errors; SSE
Binds 127.0.0.1 only; CORS limited to localhost origins; upload size cap (default 20 MB); RFC 9457 problem+json errors; OpenAPI exported to contracts/.
1 · Ingestion and Sanitization
Bytes → pages → characters → normalized text with an offset map → clause tree
Every downstream span refers to original character offsets, so a quote always round-trips: doc.text[start:end] == quote. Hidden content is quarantined and reported, never deleted from the record.
2 · Retrieval and Context
Find candidate clauses per topic and question; expand cross-references and definitions; look up statute context
Hybrid BM25 plus EmbeddingGemma with reciprocal-rank fusion (k = 6). Cross-reference expansion pulls in 'subject to Clause 7.2'. Packs and tables are YAML.
3 · Gemma Agent Orchestrator
Planner (DAG) runs: classify → choose pack → per-topic checklist NLI → cards → triage. Plus Ask and Scenario agents on demand.
A deterministic DAG for analysis (reliable) and a bounded tool-using agent for questions (agentic, at most 3 tool calls) with a pipeline fallback. Results are cached by (doc HMAC, model digest, pack version, topic).
4 · Verification Gate
Decides what is allowed to reach the user
Quote verifier, distortion checker, silence double-key, advice guard and confidence tiers. Pure Python, deterministic, fully unit-tested.
5 · Triage and Escalation
Severity, exposure arithmetic, escalation routing, pre-lawyer brief
Severity comes from YAML rules over verified facts, never from a model-made score. Arithmetic runs only on verified numbers.
Privacy Kernel
Enforces and evidences the trust boundary
Egress guard, sealed vault, redacting logger, temp-file sentinel, dependency audit, attestation (Chapter 7).
Inference Runtime
Ollama serving Gemma and EmbeddingGemma on loopback
All calls go through llm/gateway.py: timeouts, one schema-repair retry, a concurrency semaphore, token accounting and latency metrics.

7. Privacy and trust architecture (the TEE question, answered honestly)
7.1 Can we use a real TEE on this hardware?
A Trusted Execution Environment (TEE) is a hardware-isolated enclave that protects code and data even from the machine's own operating system, with remote attestation to prove what ran. Examples: Intel SGX/TDX, AMD SEV-SNP, ARM CCA and NVIDIA Confidential Computing.
TEE option
Available on the team hardware?
Intel SGX (enclaves)
No. SGX was deprecated on client Core CPUs from the 11th generation onward. A current Core i9 laptop does not offer it.
Intel TDX / AMD SEV-SNP (confidential VMs)
No. These are server-platform features (Xeon / EPYC).
NVIDIA Confidential Computing (GPU TEE)
No. Data-centre GPUs only (Hopper / Blackwell data-centre parts), not GeForce RTX 5070.
Cloud confidential VMs
Not allowed. PS2 forbids sending document content to any cloud service during processing.
Important framing for the judges: a TEE solves the problem of running on someone else's computer. LexiShield runs on the user's own computer, which is already a stronger privacy position, because the data never leaves the owner's hands. On a personal device the real threats are network egress, telemetry, data left on disk, logs and other local processes. We therefore implement the three properties a TEE provides (Isolation, Sealing, Attestation) in software, aimed at those threats, and state clearly that this is not hardware-rooted.

8.2 Ingestion details
Hidden-content detector: flags characters whose fill colour is near white (≥ 0.95 luminance) on a white page, font size under 4 pt, positions outside the page box, zero-width characters (U+200B–U+200D, U+FEFF), bidi controls (U+202A–U+202E, U+2066–U+2069) and Unicode tag characters. Each finding records its page, span and preview.
Normalizer: NFKC; curly quotes → straight; dashes unified; whitespace collapsed; hyphenated line breaks joined. A per-character offset map keeps every normalized index mapped back to the original.
Segmenter: regexes for 1., 1.1, 1.1.1, (a), (i), Clause 5, ARTICLE IV, Section 3 and ALL-CAPS headings; falls back to paragraph blocks. Produces a tree with clause ids C1…Cn.
Definitions and cross-references: "Premises" means … → glossary; subject to Clause 7.2 → link. Both feed retrieval and card context.
Injection scanner: pattern set ("ignore previous instructions", "system prompt", "you are an AI", "respond with", role tags, and similar), applied with extra weight to hidden text. Matches become hidden_findings with severity HIGH and are excluded from model prompts.
Failure modes: an encrypted PDF gives 422 ENCRYPTEDPDF; no text layer gives 422 SCANNEDNOTEXT (with an optional OCR hint); a corrupt file gives 422 MALFORMEDFILE; an empty file gives 422 EMPTY_DOCUMENT. All are tested.
8.3 Tri-state checklist logic (per topic)
for topic in pack.topics:                                   # e.g. in_rental.security_deposit
    cands = hybrid.retrieve(topic.query + topic.lexicon, k=6) + xref.expand(...)
    out = gemma.structured(prompt=CHECKLIST, schema=ChecklistOut, clauses=cands)
    ev  = [verify_quote(e, doc) for e in out.evidence]       # drop anything unverified
    if out.status in (ENTAILED, CONTRADICTED) and not any(ev): status = UNCLEAR
    if out.status == NOT_MENTIONED and lexicon_hits(doc, topic): status = UNCLEAR   # silence double-key
    card = distortion_check(out.explanation, ev) -> PASS | WARN | FAIL
    card = advice_guard(card); card.tier = tier(status, ev, card.distortion)
    emit_sse('checklist.item', item); emit_sse('card.ready', card)
8.4 Distortion checker (our main differentiator)
Extract facts from both the explanation and the cited source span: money (₹ / Rs. / INR / $ / £, including lakh and crore, and amounts written in words), durations ("eleven (11) months", "30 days"), percentages, dates, counts.
Rule 1, facts subset: every fact in the explanation must exist (after normalization) in the cited span(s). If one is missing, the result is FAIL.
Rule 2, negation polarity: if the source sentence has a negated modal (shall not, may not, no … shall, without) and the explanation's matching sentence does not (or the reverse), the result is WARN.
Rule 3, party role: if the obligated party in the source ('the Licensee shall') maps to a different role than the explanation states ('the landlord must'), the result is WARN. Uses the role map from classification.
On FAIL: the source quote is shown, the explanation is withheld, and the frontend shows "We couldn't verify this explanation; read the clause or ask a professional". Counted in metrics.

A.4 Egress guard core (illustrative)
import ipaddress, sys
ALLOWED = {"127.0.0.1", "::1", "localhost"}
class EgressBlocked(RuntimeError): ...
def _ok(host):
    if host in ALLOWED: return True
    try: return ipaddress.ip_address(host).is_loopback
    except ValueError: return False                              # unknown hostname -> block
def _hook(event, args):
    if event in ("socket.connect", "socket.sendto"):
        addr = args[1]                                           # AF_UNIX paths (str) are allowed
        host = addr[0] if isinstance(addr, tuple) else None
        if host is not None and not _ok(host):
            STATS.blocked(host); raise EgressBlocked(f"blocked egress to {host}")
    elif event == "socket.getaddrinfo" and args[0] not in ALLOWED:
        STATS.blocked(args[0]); raise EgressBlocked(f"blocked DNS lookup {args[0]}")
sys.addaudithook(_hook)   # installed at app start-up; audit hooks cannot be removed
